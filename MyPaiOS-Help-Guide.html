Everything Pi can do, and exactly how to do it — chat, local models, your knowledge, images, voice, file search, autonomous coding, and a multi-agent crew. All running privately on your Mac.

🔒 100% local-first — runs on your machine 🧠 Free local models via Ollama 👤 You're the admin — optionally add more users in Settings → Users

πWhat is Pi

Pi (MyPaiOS = "My Personal AI OS") is your own private AI workspace that runs entirely on your Mac.

Think of Pi as a single home for everything AI: a chat assistant, your searchable knowledge, image and voice generation, global file search, an autonomous coding assistant, and a team of cooperating agents — all powered by free local models (no cloud, no API bill, no data leaving your machine) with the option to plug in cloud models when you want.

The core ideas

IdeaWhat it means for you
Local-firstYour prompts, files, and outputs stay on your Mac. The default models (qwen, gpt-oss) run offline via Ollama — $0, private.
One workspaceChat, knowledge, images, voice, coding, and agents all live in one app with one sidebar.
You're in controlSingle-user and admin. Risky actions (running code, sending things) are gated and ask first.
Bring your own brainPoint Pi at your Obsidian vault / folders and it answers from your notes, not just the model's training.
The π mark The logo is the math symbol π ("Pi", 3.14) in the signature red — the brand of the whole product.

🚀Getting started

Open Pi, sign in, and learn the layout in 3 minutes.

1 · Open Pi

Launch MyPaiOS from your Applications folder (or the Dock). The app opens its own window, starts the engine in the background, and shows the π splash while it loads.

Pi also runs as a normal web app. With the engine running, open:

http://127.0.0.1:7860

You can even "install" it as a PWA from your browser's address bar for an app-like window.

Power users can start the engine directly from the project folder:

./start-macos.sh
# or
./venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 7860

On this machine it also auto-starts at login (a launchd service), so it's usually already running.

2 · Sign in

Steps to log in 3 steps›
  1. Enter your username (admin) and password. The temporary password was shown once during setup — change it in Settings → Account.
  2. Leave "Remember me" checked to stay signed in for 90 days on this device (no password stored — just a secure token).
  3. Click Sign in. You land in the Chat view.

💬Chat & modes

The heart of Pi — talk to a local model, with your knowledge and tools one toggle away.

Have your first conversation 4 steps›
  1. In the composer, make sure the model picker shows a model (e.g. gpt-oss:20b or qwen2.5-coder:14b). If empty, install one from Local AI.
  2. Type your message and press Enter (use Shift+Enter for a new line).
  3. Pi streams the answer live. Click Stop any time to halt generation.
  4. Start a fresh topic with + New chat in the sidebar. Past chats are saved and searchable.

Chat mode vs Agent mode

💬 Chat mode🛠️ Agent mode
Use forQ&A, writing, brainstorming, asking about your knowledge, generating imagesTasks that need doing: run code, read/edit files, search the web, multi-step work
ToolsOff (except image generation, which auto-detects)On — bash, python, file read/write, grep, web, and more
SwitchUse the Chat / Agent toggle next to the composer.

Use your own knowledge (RAG)

The knowledge / Brain toggle (on by default) lets Pi pull relevant snippets from your indexed notes and documents before answering, and cite them. Turn it off for pure model answers. Full setup in Brain & RAG.

🗂️ Confine the agent to one folder (Workspace)

In Agent mode, Pi's file and shell tools can reach anywhere you can. Set a workspace and they're confined — enforced on the server, not just in the UI — to the folder you choose. This is the main safety control for plain Agent chat (Cowork and Code have their own folder pickers).

Set, see & clear a workspace 4 steps›
  1. Open the ＋ menu in the composer → Workspace. Browse the folder tree, or type/paste a path into the bar and press Enter. The dialog has a command box (e.g. mkdir my-project to create a folder right there), a + New folder shortcut, and a Finder ↗ button.
  2. Click Use this folder. A folder-shaped pill chip appears in the composer showing the folder's name — that's your always-visible reminder that confinement is on.
  3. Chat normally. Every request now carries the workspace, so the agent's file reads/writes and shell commands stay inside that folder.
  4. Done? Click the pill to clear it ("Workspace cleared"). The workspace persists across chats and restarts until you clear it.
Keyboard version /workspace pick opens the same browser, /workspace set /absolute/path sets it directly, /workspace clear removes it, and bare /workspace shows what's currently set. Full command list in Slash commands.
Note "Generate an image of…" works right in Chat mode — Pi detects the intent automatically. See Images.

📎 Attach files — up to 10 at once

Any chat message can carry attachments — images, PDFs, code, documents — and there are three ways to add them:

  • ＋ menu → Attach files — the classic picker.
  • Drag & drop — drop files anywhere on the chat area; the input bar lights up to show it's a drop target.
  • Paste — Cmd+V a screenshot or copied file straight into the message box.

Pending files show as a strip of chips above the composer — image thumbnails included, each with its own ✕. Four or more collapse into a single "N files" badge (click to expand, ✕ removes all). The cap is 10 files per message; the actual upload happens when you hit Send, with a spinner on each chip. If an upload fails (too large, rate-limited), the files stay in the strip so you can retry — nothing silently vanishes.

Pi can SEE images Attach a photo, screenshot or diagram (＋ menu → Attach) and ask about it — a local vision model (the qwen3-vl family) reads it on-device. If your current chat model can't see images itself, Pi folds in the vision model's description automatically. Toggle in Settings → AI Defaults → Vision.

🧮 Rich replies — diagrams, math & auto-blur

  • Mermaid diagrams — ask for "a flowchart of X as a mermaid diagram" and the ```mermaid code block renders as a live diagram right in the reply (flowcharts, sequence diagrams, and the rest of the Mermaid family).
  • Math (KaTeX) — formulas render as proper typeset math. All the common delimiters work: $…$ and \(…\) inline, $$…$$ and \[…\] for display equations.
Small print The diagram/math renderers are two small libraries fetched from a CDN when the page loads — on a fully offline Mac the raw code block shows instead of the drawing. Everything else about the reply is local as usual.
Blurred text isn't a bug With Sensitive Blur on (Settings → Appearance → Sensitive Blur, off by default), Pi scans replies for things that look secret — emails, API keys (sk-…, ghp_…, AWS…), bearer/JWT tokens, password-style values, private keys, long hashes, internal IPs — and blurs each match. Click a blurred item to reveal it, click again to re-hide. It's a display-layer shield (great for screen-sharing and screenshots); the underlying text is unchanged.
Private moment? The 👁 Nobody (incognito) button on the welcome screen starts a chat that saves no history and no memory. And typing /setup in a fresh chat walks new users through onboarding.

🪄Slash commands — drive Pi from the keyboard

localfree

Type / in the composer and around 60 commands are one keystroke away — chats, toggles, memory, tools, setup, tours. The fastest path to almost everything in this guide.

Run your first command 4 steps›
  1. Type / in the message box — an autocomplete popup opens with matching commands, grouped and described. Keep typing to filter (it matches names, aliases, and even help text).
  2. Navigate with ↑/↓, insert the highlighted command with Tab (or Enter while you're still completing). Once you've typed a full command, Enter submits it. Esc closes the popup.
  3. Add --help (or -h) to any command to see its usage — e.g. /chats --help lists every subcommand.
  4. Typos are forgiven: /rname answers "Did you mean: /rename?". And ! works as an alternate prefix — !new = /new.
Linux brain? The classic short forms all work on chats: /rm delete · /mv rename · /cd switch · /cp fork · /cat export · /tar archive · /mkdir new · /stat info. Command replies appear in the transcript but are never sent to the model — slash traffic stays out of your chat context.

🎭Prompt — Personas, tuning & Group chat

local

One small window, three superpowers: inject text around every message, chat with a named persona, or seat several models in the same conversation. (Composer ＋ menu → Prompt)

Open the ＋ menu on the message box and pick Prompt. The window has three tabs, and the footer button always says what it will do: Start Prompt, Start Persona, or Start Group. Whatever you start shows as a small chip next to the message box — click the chip's ✖ to switch it off (a Cancel button appears in the window too while something is active).

TabWhat it does
InjectA Prefix / Suffix wrapped around every message you send, plus Temperature (0–2: low = precise/code, high = creative) and Max tokens (cap reply length; slider at the top = no limit).
PersonaA named character with its own system prompt, temperature, and memory pool. Five built-ins ship: Socrates (answers only with questions), Razor (fewest words possible), Nietzsche, Spark, and Pi.
Group2–8 participants — each a model, optionally wearing a persona — talking in one conversation, sequential or parallel.
Create your own persona 4 steps›
  1. Prompt window → Persona tab → + New, and give it a name.
  2. Type rough notes into the system prompt box ("grumpy pirate chef, secretly kind") and click ✨ Expand — AI turns your notes into a full 3–6 sentence system prompt. Edit to taste.
  3. Optionally set temperature / max tokens on the Inject tab, then click Start Persona. (It reads Save & Start Persona when you've edited — the persona is saved to the dropdown for next time.)
  4. The persona's name appears as a chip by the message box and stays active until you click its ✖. Each persona keeps its own memories, separate from yours; Delete removes the persona and its memories.
Start a multi-model Group chat 4 steps›
  1. Group tab → + Add participant: pick an optional persona and a model for each. At least 2, up to 8.
  2. Pick the mode with the toggle: Sequential (default) — participants take turns, in a shuffled order each round · Parallel — everyone answers your message at once, and each reply is shared with the others so they can react next turn.
  3. Click Start Group — a fresh group conversation opens and a Group chip appears by the message box.
  4. Chat normally. Every reply is labelled with its persona/model name. Your lineup is auto-saved as a one-click preset chip in the Group tab for next time.
Why group? Give one question to a coder, a reasoner, and a generalist and watch them disagree — or seat Socrates and Nietzsche at the same table. It's Compare, but as a conversation.
It survives reloads Personas and Inject settings are saved on the server and stay active across chats until you deactivate them; a running group chat is restored after a page reload too.

🛡️Mail Guard — AI email triage

⚡ Skills — procedures Pi learns once and reuses

The Skills tab is a library of reusable procedures. Each skill is a SKILL.md file (stored under data/skills/) describing when to use it and how — optionally with runnable scripts bundled beside it. When your message matches a skill, Pi injects the best matches (up to 3 by default) into the agent's request, so it follows a proven recipe instead of re-deriving the steps every time.

Where skills come fromHow
Auto-draftedWith Settings → Auto-extract skills on, Pi drafts a skill when an agent run works out a repeatable procedure.
Hand-writtenAdd tab → Add Skill: a title, when to use it, the approach, and tags.
ImportedImport a skill package — a .zip with a SKILL.md at its root plus optional scripts/ and references.

Draft vs published: new skills start as drafts. Published skills join the index the agent searches; drafts only count once they pass an audit at or above your confidence threshold — or you publish them by hand (card menu → Publish).

Audit all — test the library automatically 4 steps›
  1. Click ✨ Audit all. It audits the currently visible skills — filter first to audit a subset, or use Select to audit specific ones. You can skip skills that already passed.
  2. Each skill runs a test → judge → fix → retry loop: Pi gives the model a task the skill should solve, judges the transcript, and lets a teacher model rewrite weak skills before retrying.
  3. Watch the live progress panel (it runs in the background — reopen Brain and it re-attaches). Passing skills get a ✓ mark; a 🎓 mark means the teacher had to rewrite it first. Failures are flagged or demoted.
  4. With Settings → Auto-approve skills on, passing skills at or above the Minimum confidence slider (default ≥ 85%) are published automatically. Off = audit results stay drafts until you approve them.

The toolbar mirrors Memories: sort (Confidence / Most used / A-Z / Recent), filters (All / Drafts / Published / Confidence ≤ N%), a search box, and Select for bulk Approve, Audit, Delete non passing, or Delete. Expand any card to read its full SKILL.md; the card menu adds Publish/Unpublish, Edit, Test, Audit, Export .zip (share a skill), and Delete.

Run a skill on demand Type /<skill-name> your request in chat and that skill's SKILL.md is pinned to your message — no waiting for auto-match. Skills can also ship real code in scripts/ (.py, .sh, .js): the agent runs the script and only its output enters the context — deterministic and token-cheap.
Imported skills are quarantined Bundled scripts from an imported .zip will not run until you review them and set trusted_exec: true in the skill's frontmatter. Reading the skill's text is safe; executing a stranger's code needs your explicit OK.

Like memories, the toggle in the Skills header turns skill injection off entirely, and Settings → Inject Skills → Max skills per request (0–12, default 3; 0 disables) caps how much gets added to each request.

📊Parallel work & capacity

Yes — you can run several things at once. Here's how it works on one Mac, and how to see your headroom.

Pi's engine is asynchronous and the model server (Ollama) is built for concurrency, so you can have multiple chats, Code, Crew, and downloads going together. By default Ollama keeps up to 3 models loaded and serves up to ~4 requests per model in parallel; anything beyond that queues (it waits its turn, it doesn't fail).

The one real limit: memory + one GPU Everything shares your Mac's unified memory (96 GB; macOS reserves ~25% so models get ~72 GB). And there's one GPU — it time‑slices, so the more you run at once, the slower each one goes. It won't crash; it shares.

📈 The Activity indicator

The Activity item in the sidebar shows a live dot (🟢/🟡/🔴 = memory pressure) and a count of running sessions. Click it for the full picture — and to stop things: since v0.9.4 Activity is the universal kill switch, so any running chat, Code or Crew session, research job, or download can be halted from here.

Read your capacity what the panel shows›
  • Memory bar — used / total, with a marker for the GPU budget, plus free GB and how much is left for models.
  • Models loaded right now — what's actually in memory using the GPU (loads on first use, unloads when idle).
  • Running now — your active Code/Crew sessions and any downloads, each with a Stop ■ control. This is the one place that can kill anything running.
  • Headroom — a plain-English hint like "~63 GB free — room for a big coder, or several smaller ones in parallel" plus "≈ N more 7B / N more 14B".
  • Parallel budget — Ollama's current loaded-model and per-model request limits.

Rough capacity on your Mac (96 GB)

Rule of thumb Watch the Activity dot: 🟢 add more freely · 🟡 you're near the GPU budget · 🔴 new big loads will queue or evict an idle model. For lots of small parallel tasks, prefer smaller models; for one hard task, give a big model the room.

🛟Troubleshooting & tips

The handful of things that occasionally trip people up.

A new model isn't responding / first reply is slow›

Large models (like qwen3-coder-next, 51 GB) load into memory on first use — expect ~25 seconds the first time after idle, then it's fast. Check it's installed in Local AI / the picker.

File search shows 🔒 "blocked by macOS"›

macOS withholds Documents/Desktop/Downloads from background apps. Grant Full Disk Access to Pi's Python in System Settings → Privacy & Security → Full Disk Access, then re-sync in Files (sidebar → Knowledge → Files).

The UI didn't update after a change›

Pi is a PWA and caches the interface. Do a hard reload (Cmd+Shift+R) to pick up UI changes.

Cloud model won't connect›

Confirm you used a developer API key (not an app subscription), pasted it in Settings → Add Models, and that the provider/base URL preset matches. Free Gemini keys are rate-limited.

Admin: restarting the engine After config/code changes, the engine is managed by a launchd service. Restart it with: 
launchctl unload ~/Library/LaunchAgents/com.piaos.paios.plist
launchctl load -w ~/Library/LaunchAgents/com.piaos.paios.plist
(A plain kill won't work — the service auto-restarts.)
